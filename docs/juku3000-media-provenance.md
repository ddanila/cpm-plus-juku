# Juku 3000 native media boundary

The published Juku 3000 game disks are valuable museum and compatibility
inputs, but they are not vendored into this distribution.

The locally audited `J3KGAME2.JUK` matches the Juku 3000 catalogue exactly:

- catalogue/repository revision: `7b08a48a14b9c266a05af76517456575640e0599`;
- bytes: 819,200;
- SHA-1 printed by the catalogue and independently reproduced locally:
  `2e5703cf190f8e564bb1be844d5963711148e242`;
- local SHA-256:
  `39a66f3c6198cad421249d5cc2ba2821054d7f7186b845848d49273a2ccb8c0d`;
- published source:
  `https://elektroonikamuuseum.ee/failid/juku/tarkvara/J3KGAME2.JUK`.

Its directory combines original Juku software, modern ports, data/fonts, and
programs derived from historical commercial games. The catalogue identifies
authors and porters but does not grant one image-wide redistribution license.
Consequently `J3KGAME2.JUK` remains an owner-supplied, read-only `--drive-b`
input. The same rule applies to `J3KGAME1.JUK` unless a file-by-file license
manifest is established.

`cpm-plus-juku-apps.juk` is deliberately separate. It proves the native
geometry and B: load path using only project-approved material. More games may
enter that generated image only after source, author, version, license, and
checksum are recorded for every required program and companion file. This is a
licensing boundary, not a technical limitation: the production server and the
CP/M Plus BIOS already support either physical image unchanged.
