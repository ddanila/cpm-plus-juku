# CS00015 blank-video isolation

Status: **BOARD-LOCAL VIDEO-DATA FAULT ISOLATED; COMPONENT NOT YET LOCATED**

On 2026-08-21 CP/M Plus booted normally on CS00015 fitted with JukuNet C8,
but two known-good monitors showed no picture. One monitor recognized sync.
The same monitor and cable displayed the stock ROM console on CS00014.

Changing CS00015 S21 among `07h` (80x24), `03h` (53x24), and `01h`
(40x24) did not produce visible pixels. In every configuration C8 Fastboot
V16 completed and normal A: requests proved that CP/M was running. N4 then
captured the complete banner and prompt. `STATUS` reported raw S21 `01h`,
video mode 0 (40x24), and English locale as expected.

`DIAG VIDEO` reported PASS, but source review showed that this test only
checks the published mode range and BIOS console-output readiness. It does not
read framebuffer RAM or prove a physical pixel path. Its result is therefore
not display-path evidence.

## Raw framebuffer probe

`src/vidprobe.asm` is a physical service probe, not an ordinary application.
It bypasses the C8 console, applies the complete stock D54/D55 40x24 timing
sequence without touching the live D57 serial clock, maps framebuffer RAM,
fills all 9,600 bytes with alternating `55h`/`AAh`, reads every byte back, and
restores the original memory mode. The pattern is intentionally retained;
subsequent console output overwrites only the cells it uses.

The first minimal CS00015 run applied the final stock raster counts and wrote
the raw pattern. The monitor retained sync but remained blank. The enhanced
run added byte-for-byte framebuffer readback and returned:

```text
VIDPROBE: stock 40x24 timing, raw 55/AA framebuffer
VRAM READBACK PASS
```

An intermediate enhanced build reissued D54/D55 control words but initially
failed to reload their channel-0 counts. On CS00014 that build lost sync. It is
rejected and was replaced immediately; this was a probe defect, not a machine
finding. The corrected build reloads D55 channel 0 with `0139h` and D54
channel 0 with `64h` before the established channel-1/channel-2 raster counts.

## CS00014 control

CS00014 used the same serial adapter, monitor, cable, all-RAM CP/M Plus system,
A: image geometry, and corrected `VIDPROBE.COM`. Its stock ROM and normal CP/M
display were visible before the probe. The corrected probe then produced:

- stable sync;
- a full visible field of vertical stripes;
- `VRAM READBACK PASS` and the subsequent `A>` visibly rendered over the
  retained stripes.

This positive control validates the probe, timer sequence, framebuffer
pattern, monitor, and cable. The paired result proves that CS00015 can execute
CP/M, program its raster, generate sync, and read/write framebuffer RAM, but
does not deliver those stored pixel bits to the visible output. The remaining
fault is board-local after CPU-visible framebuffer storage: investigate read
addressing/output enable, pixel serialization or shift logic, blanking/video
gating, and the analog pixel-output path. CP/M and C8 console rendering are not
the cause of the observed blank screen.

## Boot observations during the control

The native C host's default 120-second deadline expired at stock record `4Bh`
(75 decimal) of 129. Repeating with `--timeout 300` completed with 389 ACKs,
zero rejects, and entered NetDisk normally.

RESET after the interrupted load did not restore a decodable Janet session.
The host received 9,826 bytes but decoded no valid request at the independently
verified 9600/8O1 configuration. A full CS00014 power cycle restored the first
request immediately. This establishes that RESET did not clear all relevant
interrupted serial/timer state; it does not identify a specific surviving
D57 or 8251 register.

Three attempts to use the retained stock-ROM V15 diagnostic host stopped at
the ROM's `LOAD 01`: low-latency compact execute, conservatively guarded
compact execute, and the original padded execute. Each accepted the one stock
record and the host sent the V15 extension/stream with zero reported retries,
but no final reply, CP/M disk request, or prompt followed. V15 is therefore not
claimed for this CS00014 ROM/configuration. The full stock loader is the
qualified control path.
